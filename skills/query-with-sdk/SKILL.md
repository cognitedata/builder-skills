# Query with the Generated SDK

Use the type-safe SDK generated by `sdk-generation-mentor` to read from your CDF data model at runtime.

> **Read-only.** The generated SDK supports only reads: `query`, `getById`, `count`, `search`, `aggregate`. It cannot create, update, or delete. For writes use `client.instances.upsert` / `client.instances.delete` directly — see **`dm-limits-and-best-practices`** for batching and concurrency.

## Prerequisite

Run **`sdk-generation-mentor`** first. The generated files must exist under `src/generated_sdks/<name>/`.

---

## Step 1 — Find your generated SDK and read its types

```bash
ls src/generated_sdks/
```

Each subdirectory is one SDK. The files:

- `index.ts` — exports `createSdk(client): Sdk` and the `Sdk` type, and re-exports all view + operation types
- `types.generated.ts` — **the source of truth.** Every view's fields, filter inputs, and relations. Read this first.
- `operations.generated.ts` — exact result shapes per operation (what `query` vs `getById` return, including which relation fields appear)
- `views.generated.ts` — view metadata used by the runtime
- `schema.graphql` — the full data model schema (alternative reference for views and relations)
- `test-helpers.ts` — `makeMockSdk()` for tests

```bash
cat src/generated_sdks/<name>/types.generated.ts   # discover views, fields, filters, relations
```

---

## Step 2 — Instantiate the SDK

```ts
import { createSdk } from '../generated_sdks/<name>';

const sdk = createSdk(client); // no network call — instantiation is synchronous
```

The `client` is your authenticated `CogniteClient` (from `useCogniteSdk()` in `@cognite/app-sdk/react`, or `useDune()` for the classic Dune setup — match your app's infra).

---

## Step 2b — Handle the first-load auth bump

On first load the host needs a brief moment before it can mint a token, so a read issued immediately can come back `401` — it succeeds once the token is available. Keep this on the SDK side: retry a transient `401` a couple of times with a short backoff. Each retry re-issues the request, which picks up a freshly-minted token. A small wrapper covers every call:

```ts
import { CogniteError } from '@cognite/sdk';

async function withAuthRetry<T>(fn: () => Promise<T>, retries = 2): Promise<T> {
  for (let attempt = 0; ; attempt++) {
    try {
      return await fn();
    } catch (err) {
      if (err instanceof CogniteError && err.status === 401 && attempt < retries) {
        await new Promise((resolve) => setTimeout(resolve, 500 * 2 ** attempt));
        continue;
      }
      throw err;
    }
  }
}

const result = await withAuthRetry(() => sdk.cogniteAsset.query({ limit: 25 }));
```

Keep `retries` small so a genuine auth failure still surfaces quickly. Using React Query? The same idea fits its `retry` option — retry a couple of times when the error is a `401`.

## Step 3 — Call the methods (resource-namespaced)

The SDK is **namespaced per view**: `sdk.<resource>.<query | getById | count | search | aggregate>(...)`, where `<resource>` is the camelCase view name (e.g. view `CogniteAsset` → `sdk.cogniteAsset`). There is no generic `sdk.query<View>()`.

### List / filter / paginate / sort

```ts
const result = await sdk.cogniteAsset.query({
  filter: { name: { eq: 'Pump A' } },                 // typed filter input for the view
  sort: [{ field: 'name', direction: 'ascending' }],  // query sort: 'ascending' | 'descending'
  limit: 25,
  cursor: pageInfo?.endCursor,                         // pagination
});
// result.items     -> view rows
// result.pageInfo  -> { hasNextPage: boolean; endCursor: string | null }
```

### Get by instance id

```ts
const asset = await sdk.cogniteAsset.getById({ space: 'my-space', externalId: 'asset-123' });
// asset: view row | null   (flat space/externalId — no instanceId wrapper)
```

### Count (returns the number directly)

```ts
const total = await sdk.cogniteAsset.count({ filter: { name: { prefix: 'Pump' } } });
// total: number
```

### Full-text search

```ts
const result = await sdk.cogniteAsset.search({
  query: 'pump failure',
  filter: { /* optional, same filter input as query */ },
  properties: ['name', 'description'],   // optional: scope the search to specific fields
  limit: 10,
});
```

> **Search has no cursor** — it cannot paginate. Use `query` (which has `cursor`) for paged lists; treat `search` as a single capped result set.

## Step 3b — Project fields with `select` (fetch less)

Pass `select` to fetch only the view properties you need. This trims the payload; the return type becomes a `Partial` of the view (only requested fields are guaranteed). **Node identity (`space`, `externalId`) is always returned and is not selectable** — the `select` type excludes it, so don't list it.

```ts
const result = await sdk.cogniteAsset.query({
  select: ['name', 'description'],   // identity comes back automatically
  limit: 25,
});
// result.items[0].space / .externalId  -> always present
// result.items[0].name / .description  -> present (selected)
// other fields                          -> not fetched
```

`search` accepts `select` too. (`select` chooses which scalar fields to return; `properties` on `search` chooses which fields the text query matches.)

## Step 3c — Relations

Check `types.generated.ts` to see which fields are relations. How they resolve:

- **Direct relations** are included on list/`query` results as references, and resolved with fields on `getById`.
- **Reverse relations / connection fields** appear on `getById` results.

To fetch records *related to* a given instance, the efficient pattern is usually to **query the related view directly by its back-reference filter** — not to walk connections off `getById`:

```ts
// Work orders for an asset (direct relation on the order):
await sdk.cogniteMaintenanceOrder.query({ filter: { mainAsset: { eq: assetRef } } });

// Time series for an asset (list relation):
await sdk.cogniteTimeSeries.query({ filter: { assets: { containsAny: [assetRef] } } });

// where assetRef = { space, externalId }
```

This returns full rows in one call and avoids `getById` resolving connection lists you don't need. Use `getById` when you specifically want one instance plus its directly-modelled relations.

## Step 4 — Use in a React component or hook

Keep data fetching in custom hooks, not in components directly. The auth hook to use depends on which Flows auth flow the app uses — check `app.json` (`"infra": "appsApi"` → Apps API flow, otherwise Classic). See the **`setup-flows-auth`** skill for full details.

### Classic flow (`@cognite/dune`)

```ts
import { useMemo } from 'react';
import { useDune } from '@cognite/dune';
import { createSdk, type Sdk } from '../generated_sdks/<name>';

export function useSdk(): Sdk | null {
  const { sdk, isLoading } = useDune();
  return useMemo(
    () => (!isLoading && sdk ? createSdk(sdk) : null),
    [sdk, isLoading]
  );
}
```

### Apps API flow (`@cognite/app-sdk`)

`CogniteSdkProvider` handles the loading and error states itself via `loadingFallback` / `errorFallback` — so `useCogniteSdk()` always returns a ready, authenticated client. No null check or `isLoading` guard is needed.

The canonical wiring (matches the `@cognite/cli` app template):

```tsx
// src/App.tsx
import type { ComponentProps } from 'react';
import { CogniteSdkProvider, useCogniteSdk } from '@cognite/app-sdk/react';
import { createSdk } from '../generated_sdks/<name>';

function AppContent() {
  // client is always authenticated here — provider handles loading/error states
  const client = useCogniteSdk();
  const sdk = createSdk(client);
  // ... use sdk
}

type AppProps = {
  deps?: ComponentProps<typeof CogniteSdkProvider>['deps'];
};

function App({ deps }: AppProps) {
  return (
    <CogniteSdkProvider
      loadingFallback={<div>Loading project...</div>}
      errorFallback={<div>Failed to connect to Fusion host</div>}
      deps={deps}
    >
      <AppContent />
    </CogniteSdkProvider>
  );
}
```

The `deps` prop is forwarded from `App` to `CogniteSdkProvider` specifically to enable testing — pass mock `connectToHostApp` / `createClient` implementations without touching real auth (see Step 5).

For hooks that are used across many components, wrap with `useMemo` to keep the SDK reference stable:

```ts
import { useMemo } from 'react';
import { useCogniteSdk } from '@cognite/app-sdk/react';
import { createSdk, type Sdk } from '../generated_sdks/<name>';

export function useSdk(): Sdk {
  const client = useCogniteSdk();
  return useMemo(() => createSdk(client), [client]);
}
```

### Querying data with TanStack Query

Wire the SDK into `useQuery` for caching, loading states, and error handling.

**Classic flow** — `useSdk()` returns `Sdk | null`, so guard with `enabled`:

```ts
import { useQuery } from '@tanstack/react-query';

export function useCogniteAssetList(filter?: { name?: { eq: string } }) {
  const sdk = useSdk(); // Sdk | null
  return useQuery({
    queryKey: ['cogniteAsset', filter],
    queryFn: () => sdk!.cogniteAsset.query({ filter, limit: 25 }),
    enabled: sdk !== null,
  });
}
```

**Apps API flow** — `useSdk()` always returns `Sdk` (provider guarantees auth), no guard needed:

```ts
import { useQuery } from '@tanstack/react-query';

export function useCogniteAssetList(filter?: { name?: { eq: string } }) {
  const sdk = useSdk(); // always Sdk
  return useQuery({
    queryKey: ['cogniteAsset', filter],
    queryFn: () => sdk.cogniteAsset.query({ filter, limit: 25 }),
  });
}
```

## Step 5 — Mock in tests with `makeMockSdk`

`test-helpers.ts` exports `makeMockSdk(overrides)`. Override only the namespaced methods a test touches; everything else returns a sensible default. Inject the mock via dependency injection — never import the real SDK in tests.

```ts
import { vi } from 'vitest';
import { makeMockSdk } from '../generated_sdks/<name>/test-helpers';

const sdk = makeMockSdk({
  cogniteAsset: {
    query: vi.fn().mockResolvedValue({
      items: [{ space: 's', externalId: 'asset-1', name: 'Pump A' }],
      pageInfo: { hasNextPage: false, endCursor: null },
    }),
  },
});

renderHook(() => useMyHook(sdk));
```

## Done

Queries run in-process against DMS — no GraphQL endpoint, no extra network hop. When the data model changes, regenerate:

```bash
# Regenerate all SDKs configured in app.json
npx @cognite/cli@1.4.0-alpha.sdk-gen apps sdk generate --interactive

# Regenerate a specific SDK by name
npx @cognite/cli@1.4.0-alpha.sdk-gen apps sdk generate <name> --interactive
```

For writes, use `client.instances.upsert` / `client.instances.delete` — the generated SDK is read-only.
