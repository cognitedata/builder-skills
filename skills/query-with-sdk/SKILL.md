# Query with the Generated SDK

Use the type-safe SDK generated by `use-sdk-codegen` to read from your CDF data model at runtime.

> **Read-only.** The generated SDK only supports read operations: `query`, `getById`, `search`, `count`, and `aggregate`. It does not support creating, updating, or deleting instances. For writes, use `client.instances.upsert` / `client.instances.delete` directly — see the **`dm-limits-and-best-practices`** skill for batching and concurrency patterns.

## Prerequisite

Run **`use-sdk-codegen`** first. The generated files must exist under `src/generated_sdks/<name>/`.

---

## Step 1 — Find your generated SDK

```bash
ls src/generated_sdks/
```

Each subdirectory is one SDK. Its `index.ts` exports:
- `createSdk(client: CogniteClient): Sdk` — factory function
- `Sdk` — the fully-typed SDK interface
- Per-view operation types (re-exported)

To discover what views, properties, and relations are available, read `schema.graphql` in the SDK directory — it is the authoritative description of the data model:

```bash
cat src/generated_sdks/<name>/schema.graphql
```

---

## Step 2 — Instantiate the SDK

Pass your authenticated `CogniteClient` to `createSdk`. In a Flows app this typically lives in a hook or context:

```ts
import { createSdk } from '../generated_sdks/<name>';

// client comes from useDune() or AppSdkAuthProvider
const sdk = createSdk(client);
```

No network connection is made at instantiation — the SDK is a thin wrapper around in-process graphql-js execution backed by DMS.

---

## Step 3 — Query views

All generated methods are async and return typed results. Replace `<ViewName>` with the PascalCase name of your DMS view.

### List / filter / paginate

```ts
const result = await sdk.query<ViewName>({
  limit: 25,
  cursor: pageInfo?.endCursor,     // for pagination
  filter: {
    status: { eq: 'active' },      // typed filter input
  },
  sort: [{ field: 'createdTime', direction: 'DESC' }],
});
// result.items: ViewName[]
// result.pageInfo: { endCursor, hasNextPage }
```

### Get by instance ID

```ts
const item = await sdk.getById<ViewName>({
  instanceId: { space: 'my-space', externalId: 'asset-123' },
});
// item: ViewName | null
```

### Count

```ts
const { count } = await sdk.count<ViewName>({
  filter: { status: { eq: 'active' } },
});
```

### Full-text search

```ts
const result = await sdk.search<ViewName>({
  query: 'pump failure',
  limit: 10,
});
```

## Step 3b — Querying relations

If a view has relation properties (direct relations, edges, or reverse relations), they are resolved automatically in a single SDK call — no extra fetches needed. Check `schema.graphql` to see which fields are relations (they reference other types rather than scalars).

```ts
const result = await sdk.queryWorkOrder({
  filter: { status: { eq: 'active' } },
  limit: 25,
});

// Scalar fields
result.items[0].title          // string
result.items[0].createdTime    // number

// Relation fields — resolved in the same call
result.items[0].assignedTo     // Asset | null  (direct relation)
result.items[0].operations     // Operation[]   (reverse relation or edge)
```

The SDK handles the multi-step DMS query internally. Never write separate queries to follow relations manually — just select the relation field and let the SDK resolve it.

## Step 4 — Use in a React component or hook

Keep data fetching in custom hooks, not in components directly. The auth hook to use depends on which Flows auth flow the app uses — check `app.json` (`"infra": "appsApi"` → Apps API flow, otherwise Classic). See the **`setup-flows-auth`** skill for full details.

### Classic flow (`@cognite/dune`)

```ts
import { useMemo } from 'react';
import { useDune } from '@cognite/dune';
import { createSdk, type Sdk } from '../generated_sdks/<name>';

export function useSdk(): Sdk | null {
  const { sdk, isLoading } = useDune();
  return useMemo(
    () => (!isLoading && sdk ? createSdk(sdk) : null),
    [sdk, isLoading]
  );
}
```

### Apps API flow (`@cognite/app-sdk`)

`CogniteSdkProvider` handles the loading and error states itself via `loadingFallback` / `errorFallback` — so `useCogniteSdk()` always returns a ready, authenticated client. No null check or `isLoading` guard is needed.

The canonical wiring (matches the `@cognite/cli` app template):

```tsx
// src/App.tsx
import type { ComponentProps } from 'react';
import { CogniteSdkProvider, useCogniteSdk } from '@cognite/app-sdk/react';
import { createSdk } from '../generated_sdks/<name>';

function AppContent() {
  // client is always authenticated here — provider handles loading/error states
  const client = useCogniteSdk();
  const sdk = createSdk(client);
  // ... use sdk
}

type AppProps = {
  deps?: ComponentProps<typeof CogniteSdkProvider>['deps'];
};

function App({ deps }: AppProps) {
  return (
    <CogniteSdkProvider
      loadingFallback={<div>Loading project...</div>}
      errorFallback={<div>Failed to connect to Fusion host</div>}
      deps={deps}
    >
      <AppContent />
    </CogniteSdkProvider>
  );
}
```

The `deps` prop is forwarded from `App` to `CogniteSdkProvider` specifically to enable testing — pass mock `connectToHostApp` / `createClient` implementations without touching real auth (see Step 5).

For hooks that are used across many components, wrap with `useMemo` to keep the SDK reference stable:

```ts
import { useMemo } from 'react';
import { useCogniteSdk } from '@cognite/app-sdk/react';
import { createSdk, type Sdk } from '../generated_sdks/<name>';

export function useSdk(): Sdk {
  const client = useCogniteSdk();
  return useMemo(() => createSdk(client), [client]);
}
```

### Querying data with TanStack Query

Wire the SDK into `useQuery` for caching, loading states, and error handling.

**Classic flow** — `useSdk()` returns `Sdk | null`, so guard with `enabled`:

```ts
import { useQuery } from '@tanstack/react-query';

export function use<ViewName>List(filter?: { status?: { eq: string } }) {
  const sdk = useSdk(); // Sdk | null
  return useQuery({
    queryKey: ['<viewName>', filter],
    queryFn: () => sdk!.query<ViewName>({ filter, limit: 25 }),
    enabled: sdk !== null,
  });
}
```

**Apps API flow** — `useSdk()` always returns `Sdk` (provider guarantees auth), no guard needed:

```ts
import { useQuery } from '@tanstack/react-query';

export function use<ViewName>List(filter?: { status?: { eq: string } }) {
  const sdk = useSdk(); // always Sdk
  return useQuery({
    queryKey: ['<viewName>', filter],
    queryFn: () => sdk.query<ViewName>({ filter, limit: 25 }),
  });
}
```

## Step 5 — Mock the SDK in tests

`test-helpers.ts` exports `makeMockSdk()` which returns a typed mock you can customise per test:

```ts
import { makeMockSdk } from '../generated_sdks/<name>/test-helpers';

const mockSdk = makeMockSdk({
  query<ViewName>: vi.fn().mockResolvedValue({
    items: [{ externalId: 'asset-1', status: 'active' }],
    pageInfo: { hasNextPage: false, endCursor: null },
  }),
});

// Inject via dependency injection — never import the real SDK directly in tests
renderHook(() => useMyHook(mockSdk));
```

---

## Done

The SDK queries run entirely in-process — no GraphQL server to stand up, no extra network hop. When the data model changes, re-run `npx @cognite/cli apps sdk generate <name>` and the TypeScript types update automatically.

For writing data back to CDF, use `client.instances.upsert` / `client.instances.delete` — the generated SDK is read-only.
